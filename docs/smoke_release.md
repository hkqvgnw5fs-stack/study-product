# Дымовой набор тестов для релиза

## 1. Цель

Этот документ описывает минимальный набор проверок, которые нужно выполнить перед каждым релизом. Если хотя бы одна проверка с пометкой **BLOCK** не проходит, релиз ЗАПРЕЩЁН.

Цель дымового набора — быстро убедиться, что продукт "живой" и его можно показывать пользователям или передавать на дальнейшее тестирование.

## 2. Подготовка окружения

Перед запуском проверок выполните:

1. Открыть терминал в папке проекта
2. Проверить версию Python: `python --version` (должна быть 3.8 или выше)
3. Создать виртуальное окружение (если ещё нет): `python -m venv .venv`
4. Активировать виртуальное окружение:
   - Windows: `.venv\Scripts\activate`
   - Mac/Linux: `source .venv/bin/activate`
5. Установить зависимости: `pip install -r requirements.txt`
6. Команда запуска проекта: `python main.py` (или `python src/app.py`)

## 3. Критерии решения

**Релиз РАЗРЕШЁН**, если:
- Все проверки с пометкой **BLOCK** пройдены успешно

**Релиз ЗАПРЕЩЁН**, если:
- Не пройдена хотя бы одна проверка с пометкой **BLOCK**

Проверки с пометкой **WARN** не блокируют релиз, но требуют фиксации проблемы.

## 4. Список проверок

### SMK-01: Проверка окружения
- **Тип:** Окружение
- **Важность:** BLOCK
- **Шаги:**
  1. Активировать виртуальное окружение
  2. Выполнить `python --version`
  3. Выполнить `pip install -r requirements.txt`
- **Ожидаемый результат:** Версия Python 3.8+, зависимости устанавливаются без ошибок
- **Почему BLOCK:** Без правильного окружения программа не запустится

---

### SMK-02: Запуск программы
- **Тип:** Запуск
- **Важность:** BLOCK
- **Шаги:**
  1. Выполнить команду запуска: `python main.py`
- **Ожидаемый результат:** Программа запускается без ошибок, появляется меню или приглашение ввода
- **Почему BLOCK:** Если программа не запускается, дальше проверять нечего

---

### SMK-03: Создание задачи (или выполнение основной функции)
- **Тип:** Функциональная
- **Важность:** BLOCK
- **Шаги:**
  1. В программе выбрать команду создания задачи (например, `add` или `create`)
  2. Ввести название: `Тестовая задача`
  3. Ввести описание: `Проверка дымового набора`
- **Ожидаемый результат:** Программа сообщает, что задача создана, возвращает ID или подтверждение
- **Почему BLOCK:** Без создания задач продукт бесполезен

---

### SMK-04: Просмотр списка задач
- **Тип:** Функциональная
- **Важность:** BLOCK
- **Шаги:**
  1. В программе выбрать команду просмотра списка (например, `list` или `show`)
- **Ожидаемый результат:** В списке отображается созданная задача `Тестовая задача`
- **Почему BLOCK:** Пользователь должен видеть свои задачи

---

### SMK-05: Изменение статуса задачи
- **Тип:** Функциональная
- **Важность:** BLOCK
- **Шаги:**
  1. Выбрать команду изменения статуса (например, `update` или `status`)
  2. Указать ID созданной задачи
  3. Ввести новый статус (например, `done` или `в работе`)
- **Ожидаемый результат:** Статус задачи изменён, при повторном просмотре списка виден новый статус
- **Почему BLOCK:** Изменение статуса — ключевая функция

---

### SMK-06: Сохранение данных
- **Тип:** Данные
- **Важность:** BLOCK
- **Шаги:**
  1. Выбрать команду сохранения (например, `save` или `exit` с автосохранением)
  2. Проверить, что файл данных создался или обновился
- **Ожидаемый результат:** Файл данных (например, `tasks.json`) создан/обновлён без ошибок
- **Почему BLOCK:** Без сохранения данные теряются после перезапуска

---

### SMK-07: Восстановление данных после перезапуска
- **Тип:** Данные
- **Важность:** BLOCK
- **Шаги:**
  1. Закрыть программу (Ctrl+C или команда `exit`)
  2. Запустить программу снова: `python main.py`
  3. Выбрать команду просмотра списка
- **Ожидаемый результат:** Созданная ранее задача `Тестовая задача` присутствует в списке с сохранённым статусом
- **Почему BLOCK:** Если данные не восстанавливаются, сохранение бесполезно

---

### SMK-08: Поиск задачи
- **Тип:** Функциональная
- **Важность:** WARN
- **Шаги:**
  1. Выбрать команду поиска (например, `search` или `find`)
  2. Ввести ключевое слово: `Тестовая`
- **Ожидаемый результат:** Поиск находит созданную задачу
- **Почему WARN:** Поиск важен, но без него продукт всё ещё работает

---

### SMK-09: Ошибочный ввод (пустое название)
- **Тип:** Ошибка
- **Важность:** WARN
- **Шаги:**
  1. Выбрать команду создания задачи
  2. Ввести пустое название (нажать Enter сразу)
- **Ожидаемый результат:** Программа выдаёт понятное сообщение об ошибке (например, "Название не может быть пустым"), не падает
- **Почему WARN:** Программа должна быть устойчивой к ошибкам пользователя

---

### SMK-10: Отсутствие файла данных
- **Тип:** Ошибка
- **Важность:** WARN
- **Шаги:**
  1. Закрыть программу
  2. Переименовать или удалить файл данных (например, `tasks.json` → `tasks_backup.json`)
  3. Запустить программу снова
- **Ожидаемый результат:** Программа не падает, создаёт пустой файл или сообщает о проблеме корректно
- **Почему WARN:** При первом запуске файла данных может не быть, программа должна это пережить

## 6. Пояснение выбора (задание для закрепления)

### Почему SMK-02 (Запуск программы) — BLOCK?

Если программа не запускается, пользователь вообще не может ей пользоваться. Это самая критичная ошибка, которая делает продукт полностью бесполезным. Без запуска нет смысла проверять что-либо ещё.

**Последствия:** Невозможность использования продукта, потеря доверия пользователя.

---

### Почему SMK-07 (Восстановление данных после перезапуска) — BLOCK?

Если данные не сохраняются и не восстанавливаются, пользователь теряет всю свою работу после перезапуска. Это делает продукт ненадёжным и бесполезным для реального использования.

**Последствия:** Потеря данных пользователя, невозможность долгосрочной работы.
