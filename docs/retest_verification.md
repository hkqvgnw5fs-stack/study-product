Лабораторная работа: Ретест и верификация исправления
1. Цель работы
Научиться воспроизводить дефект, фиксировать состояние "до исправления", выполнять ретест после исправления и проводить верификацию, чтобы убедиться, что исправление не сломало соседнюю функциональность.

2. Краткое описание дефекта
Название: Падение программы при создании задачи с пустым названием

Где проявляется: Консольный модуль управления задачами, команда создания задачи (add)

Что происходит: При попытке создать задачу с пустым названием программа аварийно завершается с исключением

Что должно происходить: Программа должна отклонить пустое название, вывести сообщение об ошибке и продолжить работу

Не создавать задачу с пустым названием

Не завершаться аварийно

Вернуть пользователя в главное меню

def create_task(title):

        raise ValueError("title cannot be empty")

После исправления код выглядит так:

python

        return None
    # ... создание задачи

10. Почему нельзя закрывать дефект без ретеста
Если закрыть дефект без ретеста, могут произойти следующие проблемы:

Ложное чувство уверенности — разработчик думает, что всё исправлено, а на самом деле дефект остался

Появление нового дефекта — исправление может сломать соседнюю функциональность, и никто этого не заметит

Потеря доверия — если баг вернётся, пользователи потеряют доверие к команде

Трата времени — вместо одного раза придётся исправлять баг снова и снова
